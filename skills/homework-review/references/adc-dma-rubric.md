# ADC + DMA 作业评分参考

## 适用范围

适用于嵌入式 C、STM32、HAL、CubeMX、FreeRTOS、ADC + DMA 类实验作业。若作业不是 ADC + DMA，可沿用评分结构，并把专项检查项替换为实际外设或项目目标。

## 100 分制

| 维度 | 分值 | 评分要点 | 高分标准 |
| --- | ---: | --- | --- |
| A. 作业完整性与表达 | 10 | 标题、学习目标、知识结构、实验内容、截图/代码/问答组织清楚。 | 阅读路径清晰；关键证据可定位；图文对应。 |
| B. 知识点总结正确性 | 25 | ADC/SAR/DMA/ADC+DMA/CPU-DMA 并行/FreeRTOS 同步等概念是否准确。 | 能用自己的话解释原理、适用场景、关键参数和常见误区。 |
| C. 效果截图与实验现象 | 20 | 串口日志、CubeMX、代码运行截图、map/Understand 截图、现象标注。 | 截图能证明关键现象，日志与文字解释一致，有异常或对比分析。 |
| D. 代码片段质量 | 15 | HAL_ADC_Start_DMA、回调、buffer、邮箱/队列/信号量、换算公式等片段。 | 片段语法基本正确，API 使用场景合理，能支撑实验结论。 |
| E. 面试题/思考题回答 | 20 | 邮箱/队列/信号量、data/bss/heap/stack、ScanConvMode、ContinuousConvMode、EOCSelection、采样时间、ADC 类型等。 | 回答准确、有区分度，能结合代码或截图说明。 |
| F. 工程意识与规范 | 10 | 参数表、命名、注释、静态分析意识、map 区域理解、问题记录。 | 不只是堆截图；能体现调试、验证和工程化思路。 |

原始总分 = 六个维度得分之和 + 加分项 - 违规扣分。最终总分限制在 0 到 100。

## 分档

| 等级 | 分数 | 判定 | 处理建议 |
| --- | --- | --- | --- |
| A+ | 90~100 | 高质量候选 | 进入二次复核；可考虑优秀展示或样例库。 |
| A | 80~89 | 完成较好 | 给出优化建议；可局部展示亮点。 |
| B | 70~79 | 基本完成 | 指出关键短板；建议返修但可通过。 |
| C | 60~69 | 勉强通过 | 必须给出必改项；返修后可重评。 |
| D | <60 | 未达标 | 需要重做或补交核心材料。 |

## 扣分上限

| 情况 | 最高分上限 | 说明 |
| --- | --- | --- |
| 仅缺少完整工程源码 | 不设统一上限 | 按完整性、可复现和工程规范维度扣分；代码片段、知识总结、效果截图和面试题可正常得分。 |
| 代码片段存在明显语法/API 错误 | 视严重程度限制 D 维度得分 | 例如变量未定义、括号不闭合、ISR 调用阻塞 API、FromISR API 场景错误。 |
| 无运行日志/视频/截图证据 | C 维度最高 8/20 | 代码和理论看起来正确也需实验证据，但不直接限制总分。 |
| 核心功能缺失：未真正使用 DMA | 60 | 只用轮询读取 ADC，未达到作业主目标。 |
| 知识点总结大面积错误，且面试题回答错误 | 60 | 学习总结型作业的核心目标未达成。 |
| 存在明显竞态、越界、ISR 阻塞等高风险问题 | 75 | 即使现象偶然正确，也不能给高质量分。 |
| 疑似大段抄袭且无法解释 | 60 或更低 | 需人工复核；确认抄袭按课程规则处理。 |
| 伪造日志/截图、冒名提交 | 0~30 | 按教学纪律处理，并记录。 |

## 加分项

加分最高 +5，最终不超过 100。

| 加分项 | 建议加分 | 说明 |
| --- | ---: | --- |
| 提供关键代码片段，且语法无明显错误、API 使用合理 | +1~2 | 适用于没有完整工程但片段能说明实现思路的提交。 |
| 实现双缓冲或半传输/全传输处理，并能解释适用场景 | +1~2 | 如高频采样、波形/音频类处理。 |
| 提供完整问题排查记录和错误复盘 | +1 | 能体现调试能力。 |
| 对比轮询 ADC 与 ADC+DMA 的 CPU 占用/任务阻塞差异 | +1 | 有数据或清晰日志更佳。 |
| 代码结构可复用，能扩展到更多通道/业务任务 | +1 | 驱动封装清晰。 |

## 高质量候选门槛

- 最终总分 >= 90。
- 知识点总结正确性 >= 22/25。
- 效果截图与实验现象 >= 17/20。
- 代码片段质量 >= 12/15。
- 面试题/思考题回答 >= 18/20。
- 无红线或总分上限问题。
- 讲师或高级助教抽查 2 到 3 个关键点时，学员能解释。

## 常见必须纠错点

- ADC 分辨率：12 位 ADC 有 4096 个码值。工程映射常用 `raw * Vref / 4095.0f` 让码值 4095 对应 Vref；讨论量化步距时可说明 `Vref / 4096`。
- DMA 并行：DMA 减少 CPU 搬运负担，但 CPU 仍负责配置、启动、回调处理和异常处理。
- 零等待/立刻处理：任务可阻塞等待通知，但响应时间受中断、调度和优先级影响。
- ScanConvMode：多通道按 Rank 扫描通常需要开启；单通道一般不需要。
- ContinuousConvMode：ADC 是否连续启动下一轮转换，与 DMA circular/normal 不同。
- EOCSelection：区分每个通道转换完成和整个序列转换完成。
- 邮箱/队列：邮箱可用长度为 1 的队列配合 overwrite/peek 实现；peek 不移除消息，receive 会移除消息。
- 信号量/邮箱：信号量主要传递事件或资源计数，不传业务数据；邮箱传递最后一份数据或指针/结构体。
- ISR 日志：中断回调应尽量轻量，避免阻塞式 printf 或复杂计算。
- DMA 双缓冲：软件交替使用两个 buffer 不等同于硬件 DMA double buffer；半传输/全传输回调要说明边界。

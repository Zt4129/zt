学员可直接接收的作业反馈

反馈的读者是学员，交付的是评语，不是检查记录，也不是替学员重写整份笔记。把核查证据和推理留在检查过程中；给学员的正文只保留能帮助其定位和改正的信息。

排版根据交付渠道调整。飞书反馈文档使用原生标题层级、适量加粗和段落留白；直接粘贴到企业微信等纯文本渠道时，使用下方的纯文本示例格式。

使用自然、直接的表达，把错误判断和修正答案融进一至两段话；复杂纠错可以拆成更多短段。不要机械输出出处、原话、问题在哪里、修正等字段标签。把关键表述改写成自然转述，不逐字引用，不加任何单双引号字符，也不加笔记认为、学员认为、笔记中提到等赘语。只有在定位确实困难时，才用一行简短地点明章节、函数或配置。每条知识点或面试题反馈都要附上针对原题的参考答案，内容应完整到学员可以直接据此改写；不能只指出错因、列出应该覆盖的关键词，或让学员自己拼答案。漏答题也要先补出参考答法。代码问题给明确的修改点或短代码示意；实验/材料缺证据时，列清要补交的材料及其应证明的现象。在飞书反馈文档中，若纠错明确引用作业截图里的代码、配置或现象，且原提交有对应图片，将实际预览过的原截图附在对应纠错段落之后并加简短说明；不要只在文字中提及截图。只附直接支撑该纠错的图片，不复制无关插图或全部附件。无法读取或取得图片时不伪造，在给检查者的对话中说明。

每条知识点纠错都要先明确指出学员哪一条结论或推理错了，具体错在什么概念、分类或适用条件；不能只说不准确、建议说明或建议补充。接着直接给出修正后的完整答案，确保能独立读懂并替换原回答。先正面回答题目，再解释必要的概念区别、工作机制和适用条件；若是流程，要交代关键步骤如何衔接。不要只把绝对结论改成不一定、通常如此等措辞，却没有解释到底在什么情况下成立、为什么成立。简单事实可以短答；涉及多个启动源、不同 API 上下文或配置分支时，应把决定结论的条件讲出来，并结合本工程证据。材料不足时指出需要核对的具体型号或配置。若答案只有部分错误，应保留其正确部分；若问题是漏答或证据不足，应明确指出缺项并给出准确的补答内容或具体证据要求，不得把遗漏伪装成错误结论。

例如，纠正 Bootloader 相关回答时，仅写复位后执行什么取决于启动配置仍不足以帮助学员理解。应说明 CPU 复位后从当前启动映射的向量表读取初始 MSP 和 Reset_Handler；启动配置决定当前映射到用户 Flash、系统存储器等区域。厂商 ROM Bootloader 只在选择相应启动源时运行；用户自定义 Bootloader 是放在用户 Flash 中的另一段程序，不是每个项目上电必经的阶段。用户 Bootloader 可以检查升级状态、接收或校验固件，再跳转到 APP；普通 MCU 应用也不一定运行操作系统。涉及具体工程时，再用芯片型号、启动配置、链接地址和向量表说明实际走哪条路径。

以下示例展示反馈内容和纯文本渠道格式。生成飞书文档时，按 SKILL.md 中的飞书反馈文档排版规则应用标题样式、加粗和段落留白。

普通知识点反馈格式：

11、共享状态加锁不等于可重入

第四节把只要函数使用全局资源，即使加锁也不能重入作为结论。这里把可重入性和线程安全混在一起了。加锁可以让多个任务串行访问共享状态，但递归调用或 ISR 重入还需要单独判断。

可重入性关注函数执行过程中再次进入时能否正常工作；线程安全关注并发调用时共享数据是否受到保护。加锁可以保护共享状态，但不会自动让函数可重入。

代码问题格式：

12、队列满时读取接口可能一直等待

在 bsp_temp_humi_xxx_read 中，队列发送使用最大等待时间。队列满时，调用任务可能被挂起，所以这个接口不能保证非阻塞。

如果 APP 不能等待，把发送超时改为零，并处理队列已满的返回值。

实验或证据问题格式：

13、补充一张能看出输入变化的运行截图

请补一张包含测试条件和连续读数的截图，或附上对应日志，展示传感器输入变化与串口读数之间的对应关系。

作业标题

学员版文档不写整体检查结论、总结性评价或评分。评分、总体完成情况和给检查者的摘要写在最终对话回复中；用户明确要求时才将评分加入学员版文档。

按课程顺序列出节标题，再按全局连续编号给出问题。问题标题描述学员能理解的具体主题。正文中直接指出原结论或代码行为、解释为什么需要改，并给出可以照着修改的句子或操作。避免检查人员口吻和模板标签。

具体的材料缺项只在对应纠错下写成学员可执行的补交要求，例如提供代码分支和 commit、成功构建记录、能看出关键操作与结果的截图或视频。写清材料需要展示的内容；不要用截图无法确认、当前材料不能证明完成等检查结论代替补交要求。整体检查范围、完整 document ID、revision、媒体清单和内部核查过程留在给检查者的对话回复或内部记录中；不要在学员文档添加总结性评语或无关元数据。

纠错问答可以保留为末尾复习索引，但每条必须对应正文已指出的问题，不增加新问题。若用户要的是直接发给学员的成稿，问答应简短、自然，避免重复整段纠正内容。

纯文本渠道排版：课程标题、问题标题、反馈段落之间留一个空白行，保证复制到企业微信后仍然分段。不要使用 Markdown 标题、粗体、项目符号、表格、代码围栏、反引号、装饰符号或任何单双引号字符，包括英文直引号、英文弯引号和中文弯引号。术语、变量名和原话都直接写或转述，不要用引号突出。不要为了形式把每个问题拆成四个标签段落。技术名词、函数名和路径正常书写。输出前逐字符检查学员正文是否残留引号；发现后改成转述并复查，确认学员可以直接发送或按建议直接改，不需要先替检查者改写口吻。
